# Authentication

The Galaxy API supports two authentication mechanisms: **Clerk JWT Bearer Tokens** for production users, and a **Deterministic Development User** for local testing, CI/CD runners, and reviewer inspection.

## 1. Bearer Token (Clerk Authentication)

In production, pass the session JWT generated by Clerk in the `Authorization` HTTP header:

```http
Authorization: Bearer <clerk_jwt_token>
```

When a valid token is received, the backend verifies the signature against `CLERK_SECRET_KEY` and upserts the user record into PostgreSQL.

## 2. Default Test / Reviewer Mode

When testing endpoints locally or using Postman without Clerk active, requests without an `Authorization` header automatically resolve to the pre-seeded development user:

| Field | Value |
| :--- | :--- |
| **User ID** | `user_dev_trial_candidate` |
| **Email** | `trial@galaxy.ai` |
| **Initial Credits** | `1,000 credits` ($10.00 equivalent) |

This guarantees that Postman collections, curl commands, and reviewer evaluations run without being blocked by interactive login walls.
